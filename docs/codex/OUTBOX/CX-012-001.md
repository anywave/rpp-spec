## Cause and implementation

Previously `invalid_input_error(tick)` inferred rollback after core returned
the shared `InvalidInput` status. A past tick could also encounter an earlier
validation error, and control rollback could consume a core request/meter row
before its result was classified.

Choose the card's resolver-first option. The first executable statements of
both `resolve_data` and `resolve_control` now check
`tick < self.policy.clock()` and immediately return `ClockRollback`. This runs
before endpoint/authentication validation, path/frame/reference checks, meter
retention, previews and sends. No operation runs on a rejected rollback.
The old inference helper is removed. Every later core `Status::InvalidInput`
and `choose_latest` error maps directly to `FleetResolveError::InvalidInput`.
The exclusive mutable resolver call prevents another caller changing its
policy clock between this check and the core call.

IMPOSED choice: enforce the precondition at the fleet boundary rather than add
a new core status. It gives the requested error precedence with a small change
and leaves core/Python statuses and policy behavior unchanged. The comparison
still uses accepted core control state; data queries do not advance that clock.

`rust/FLEET.md` documents first-check precedence, unchanged-state rejection and
the direct invalid-input mapping. No wire, score, freshness, transport, crypto,
consent, reference TTL or resource limit is changed.
