## B — Rust-only final library

`rust/` is one workspace with one provisional, non-published `rpp-core` library
crate, Rust **1.85.1**, edition 2021, **zero dependencies** and a committed lockfile.
`#![forbid(unsafe_code)]` covers every module. Library code has no I/O, network,
threads, clock/random access, unsafe/FFI or cryptography; deterministic ordered
collections operate on host inputs. Python scaffolds remain outside the package.
`cargo package --list` confirmed **20 files**, no Python script or binary target.

Modules: canonical v2 addresses; separate Mobius32 golden profile; pure resolver
selection; overlay policy; in-memory scenario rendering. Migration takes an
explicit `MigrationPolicy::{NeutralRadius, ShellProjection}` with no default.
Resolver discovery, preference/default ordering, access gate and attempt outcomes
are supplied by the host; unavailable/not-found falls back with `tried_modalities`,
while denial terminates. An invalid first endpoint cannot shadow a later eligible
URI of the same modality. No storage backend, probe or identity provider is added.

Rust tests: **37 passed** = one heap-free canonical unit + Mobius32 **7** (the same five golden-check families
plus two field/raw-word cases), canonical **5**, overlay **18**, resolver **6**.
Canonical v2 and Mobius32 layouts are explicitly separate and original vectors
are untouched. Fmt and all-target Clippy `-D warnings` pass.

The crate is liftable unchanged: all manifests, sources and test data live under
its own `rust/` workspace, with no outside path dependency. Features are default
`std`, `std → alloc`, and optional `alloc`; without `std` the crate is `no_std`.
The word/byte codec, migration, ASCII numeric URI parser and caller-buffer
URI/hex formatting need no heap. Full Unicode-digit parsing and String helpers
require `alloc`, as do resolver, overlay and rendering; these compile without
`std`. The new heap-free golden test runs under both feature modes. No transport
is added. Xtensa toolchains and physical ESP32 boards were not exercised.

Actual final cross-builds passed for `riscv32imc-unknown-none-elf` with no
features and with `alloc` only. Default and alloc-only tests each pass **37**;
no-default tests pass **8**, including the same heap-free canonical golden and
all seven Mobius32 tests. Official pinned compiler and target archives were
manifest-hash-verified; exact provenance is in `rust/VALIDATION.md`. The desktop
9497-row corpus scope is unchanged. These are library cross-builds, not firmware
or board validation.

### CI, scope and IMPOSED choices

The new Ubuntu/Windows Cargo workflow is **non-advisory**: fmt, all-target Clippy
`-D warnings` and locked offline tests. Rust 1.85.1 and its components are pinned;
checkout is SHA-pinned, credentials are not persisted and contents permission is
read-only. Required-check configuration is unchanged. Hosted results are not
claimed as observed before running the new workflow.

IMPOSED: zero dependencies; provisional `publish=false` crate; separate address
profiles; caller-supplied discovery/outcomes; first eligible URI per modality;
deduplicated modality attempts; terminal access denials; explicit migration policy;
preserve URI quirks. Rust typed inputs cannot represent arbitrary Python dynamic
types/integers; raw signed input is `i64`, raw words cover all `u32`. Unicode Nd
is frozen to 15.0.0. Python's configurable huge-URI integer-conversion limit is
host policy, not cloned into the library. Overlay integer/UTF-8 limits are explicit.
Parity is established on the tested shared domain, not every Python runtime quirk.
No real verification, key exchange, transport, physical/device claim or generic
coherence/sector readout is implemented.
