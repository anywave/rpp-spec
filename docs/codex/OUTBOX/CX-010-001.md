canonical addresses and resolves their endpoint records through the existing
RPP overlay policy. It is unconditionally `no_std`, forbids unsafe code, and
uses only the existing three pinned sibling crates. There are no external
dependencies, binary targets, Python runtime files, network operations,
cryptographic algorithms, radio drivers or vendor HALs.

## Assignment and trust boundaries

The canonical specification defines fields/encoding, and RESOLVER delegates
identity authentication to another layer; neither defines an opaque-identity
to canonical-address derivation. NETWORK's separate `SHA-256(public_key)`
NodeRecord ID is not a compact-address derivation. The new fleet pair does not
silently replace or truncate that contract.

The informative `explicit-caller-assignment-v1` profile therefore requires a
matching owner-supplied AddressBinding. There is no Default, identity-only
hash, bit projection or automatic identity-derived address. Derivation means
an exact full-identity binding lookup followed by existing core encoding;
missing or mismatched bindings fail explicitly. This preserves semantic field
choices and avoids inventing a lossy identity scheme.

One configured binding is stored per registered node. Registration uses the
existing core `is_valid()` predicate, without another numeric range table or
reserved-bit filter. Full identities, control/device IDs and encoded address
words are locally unique; rejection leaves existing records unchanged. Tests
cover two distinct radius inputs that encode to the same word. No local check
claims global uniqueness, ownership, membership, consent or future routability.
Assignments are configuration, not permanent object identity; temporal address
lifecycle and reassignment are outside this prototype.

The policy node label is the entire 32-byte identity pair rendered as 64 hex
characters. Core link names are `nAAAAAAAA-epEEEEEEEE`, the registered encoded
address word and per-node endpoint ID. This reversible 20-character namespace
fits existing limits and avoids truncation, hashing and URI-path aliases.
Registry word uniqueness and the resolver's exclusive registry borrow prevent
another node/context from reusing that link state. During a resolver lifetime,
only validated reading updates are forwarded; structural bindings and endpoint
ownership cannot be substituted through the read-only registry view.

Capabilities are prior host inputs. Verification booleans default to false;
unknown failure domain zero is shared, so a different modality does not imply
independence. Registration never populates member or consent sets. Data on BLE
requires the existing policy's reviewed-adapter/tunnel eligibility. Control
additionally requires an explicitly compatible control endpoint, verified
`rpp-control` frame, matching source/recipient IDs, current host authorization,
known historical data-path context and independent current control path.

Only the latest successful primary data selection becomes the real known
reference. Alternative previews use cloned core state. An outage retains that
primary's historical failure-domain context, with no invented reference TTL;
current control readings still pass core freshness checks. Old primary,
cross-target and unselected-fallback references fail. Control alternatives are
queried from fresh pre-call clones; the real sequence/meter transition occurs
once. A checked primary route consumes itself on dispatch, uses the typed
control hook and rejects adapter-kind mismatches before callbacks. The host
still binds its adapter to the actual selected endpoint and failure domain.

Data resolution is a query. It does not advance the real send clock, perform
retries or record actual data-send meter rows. Its rollback gate is relative
to accepted core control state, not an independent monotonic history of all
query ticks. Actual sends/outcomes, first-token retry limits, metering, consent
revocation, transport identity and physical adapter binding remain host duties.
A control Ready result reserves model sequence/state; it is not delivery or
remote execution. Direct endpoint records do not invent multi-hop topology.

## IMPOSED choices and integration limits

- Explicit informative caller assignment, no default or invented identity hash;
  preserve semantic address fields and existing codec rules.
- Opaque 16+16-byte fleet pair, locally unique device control ID and encoded word;
  local bookkeeping is separate from NETWORK's NodeRecord identity contract.
- Ordinary-node registration uses core `is_valid`; binding objects preserve
  accepted reserved bytes without adding another range/bit policy.
- Per-node endpoint IDs are namespaced by the registered word; an exclusive
  registry context protects policy state from unrelated binding replacement.
- Prior capabilities fail closed and unknown failure domains are shared.
- Direct endpoint metadata, explicit compatible control endpoints, latest actual
  primary reference and core-only failover selection. Fallback lists are
  informative options, not permission for automatic post-token retries.
- Extend oracle freshness to all twelve files and protect every new hashed path.

Board models, firmware/HAL, radio/GATT/LoRa framing, actual WebSocket transport,
IP overlay/relay deployment, credential provisioning, reviewed verifier backend,
consent lifecycle and physical metering remain integration work. Existing reuse
rulings are unchanged. This task selects no new cryptography or device protocol.

+key derivation or cryptographic ownership proof is proposed here.

+AddressBinding between an exact opaque identity and an existing canonical
+address. The experimental identity is the full pair of a 16-byte lender-key
