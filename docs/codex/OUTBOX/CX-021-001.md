## Result and scope

`rpp-frag` provides a heap-free `no_std` fragment writer and fixed-slot control
reassembler with unsafe code forbidden. `Fragmenter` uses a caller buffer;
`Reassembler<SLOTS, MAX_LEN>` returns only caller-verified control frames through
`rpp_control::decode`. Public adapter traits, production dispatch/core policy,
control envelopes, RPP Python, specs, published constants and old vectors remain
unchanged. New local framing constants and a new fragment corpus are authorized
by CX-021. The existing sim-only Bluetooth scenario now actually fragments and
reassembles its control send, while all three overlay artifacts remain identical.

## Header, reuse and imposed choices

The read-only comparison is [SMALL_MTU_FRAMING.md](../../design/SMALL_MTU_FRAMING.md).
Use an underlay's existing segmentation instead of this helper: L2CAP LE
credit-based channels, GATT long writes and deployed SCHC adaptations already
have their own procedures. Local framing covers default-MTU GATT notifications
and LoRa only. There is no selected board adapter or claimed interoperability.

The five-byte header is `11100sss size-low tag-high tag-low offset`, derived
from RFC 4944 FRAGN. Size and tag are big-endian; offset is a byte offset.

- **IMPOSED:** use that header for every fragment, including offset zero, and
  replace eight-byte offset units with bytes. This permits MTU six and avoids
  alignment/padding for these small frames. It is a local derivative, not 6LoWPAN.
- **IMPOSED:** limit its datagram domain to 255 bytes; the default generic cap is
  the unchanged 112-byte control envelope. A requested generic cap above 255 is
  rejected. MTU below header plus one and empty input are rejected.
- **IMPOSED:** `SlotsFull` refuses the new datagram and never evicts a live one.
- **IMPOSED:** callers bind opaque 16-byte peer/link identifiers to ingress;
  peer/tag association is not authentication. Tags and ticks are caller supplied.

Preflight all bounds and conflicts before writes. Different-byte overlap,
changed totals for a live key and out-of-range payloads fail without poisoning
coverage. Identical duplicates change neither coverage, deadline nor remembered
tick. Expiry is half-open; a matching expired slot is cleared and returns
`Expired`, and unrelated expired slots may be reclaimed. Malformed fragments, conflicts, full live slots and rollback do not
advance the remembered tick. Completed slots are cleared on decoding success or failure.
The caller still enforces consent, membership and replay before effects.

## Static RAM and board work

Actual Rust 1.85.1 `riscv32imc-unknown-none-elf` compilation reports
`size_of::<Reassembler<4,112>>() == 1080` bytes. The crate asserts that exact size
on riscv32 and a 1,200-byte ceiling on every compiled target. An independently
compiled LLVM IR probe outside the checkout contains `[1080 x i8]`; this is not
an estimate obtained by adding field sizes. Both bare and alloc workspace cross
builds exercise the assertion. The figure excludes caller buffers, verifier,
stack usage, driver queues and radio stack; it is not total ESP32 RAM usage.

Once RADIX names a board, its adapter still needs the BLE stack/characteristic,
negotiated MTU, authenticated ingress binding, bounded queues, tag allocation,
logical tick source, reviewed caller verification, host consent/replay checks,
LoRa regional configuration where applicable and physical hardware tests. The
new BLE fixture sends in memory atomically; it models neither delays nor radios.
